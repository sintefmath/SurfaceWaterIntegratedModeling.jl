Similar to how an NBS network can be 'solved' in SUrbArea, I want to implement
corresponding functionality for 'solving' a DynNetwork.  (In fact, in the longer
run, I plan to integrate both culverts and NBS elements as components in a
DynNetwork).

Here, "solving" will mean evolving the elements' state (i.e. water content)
until an "event" happens.  An "event" is one of:
- a TRANSITORY trap filling up to its capacity and starting to spill, or
- a FULL trap going from spilling to no longer spilling, because its net inflow
  has dropped below its losses (infiltration and, later, culvert drainage).
Either kind of event changes the network topology, so it ends the current solve.
An outer loop (outside the scope of this task) would then rebuild the network
and continue.

Water is lost through direct infiltration to the ground.  Infiltration is
specified as a grid where impermeable (or completely saturated) gridcells are
attributed the value 0, whereas cells with infiltration will be given a positive
infiltration rate value.

To start with, we will stick to just lakes and rivers, but it should be possible
to expand scope to culverts and NBS elements later.

All the code lives under the /src/dynamics directory, in 'networksolver.jl'.

* Design clarifications (resolved in discussion)

These resolve ambiguities in the prose above.  The implementation must follow
them exactly.

** Three trap states

There are exactly three trap states relevant to network topology.  State is
determined by the water content V and the trap's capacity C:

| State      | Condition     | Notes                                              |
|------------+---------------+----------------------------------------------------|
| EMPTY      | V == 0.0      | Exactly zero; only lowest-level (leaf) traps       |
| FULL       | V == C        | Exactly equal to ~TrapGeometry.capacity~           |
| TRANSITORY | 0.0 < V < C   | Anything strictly in between                       |

The *caller* is responsible for ensuring these exact equalities before every call
to ~solveDynNetwork~.  The function relies on these exact values and validates
them at entry.  "Do not play around with infinitesimals or small tolerances
inside ~solveDynNetwork~ to flag changes in a trap's status" — just report
status changes to the caller and let them be handled outside.

** Caller's responsibility

The caller maintains an authoritative list of which traps are FULL (~full_traps~
in ~setup_network~'s sense).  Before every call to ~solveDynNetwork~:

- FULL traps: state must be exactly V == C.
- TRANSITORY traps: state must be strictly V < C (use ~prevfloat(C)~ if the trap
  was very recently full or nearly so).
- EMPTY lowest-level traps: state is exactly V == 0.  Only lowest-level traps
  may be EMPTY; parent traps must not appear in the network while EMPTY.

After each event, the caller must update its records and pass a fresh, valid
network to the next call:

| Event            | Caller action                                             |
|------------------+-----------------------------------------------------------|
| ~:fill~          | Add trap T to ~full_traps~; set state[T] = C[T].          |
|                  | Rebuild network via ~setup_network~.                       |
| ~:unspill~       | Remove trap T from ~full_traps~.  Pass state[T] =          |
|                  | ~prevfloat(C[T])~ to the next call (TRANSITORY).           |
|                  | Rebuild network.                                          |
| ~:empty~         | Remove parent P and its immediate children A, B from       |
|                  | ~full_traps~.  Set state[A] = ~prevfloat(C[A])~,           |
|                  | state[B] = ~prevfloat(C[B])~.  Call ~setup_network~        |
|                  | without P, A, B in ~full_traps~ (they become TRANSITORY    |
|                  | leaf nodes; if A or B were actually not emptying, a        |
|                  | ~:fill~ event fires on the very next call).                |
| ~:none~          | Steady state; no topology change; do not loop.             |
| Simultaneous     | When two traps fill at the same ODE step, only one is       |
| fills            | reported.  The caller sends ~prevfloat(C)~ for all other   |
|                  | traps not yet registered as FULL; the co-filled trap fires  |
|                  | ~:fill~ on the next call (dt ≈ 0).                         |

** Entry contract and validation

~solveDynNetwork~ checks this contract at entry and throws an error if violated:
1. Every FULL trap (state == C) must have ~DynTrap.spill_path > 0~.
2. Every TRANSITORY trap (0 < state < C) must have ~DynTrap.spill_path == 0~.
3. Every EMPTY trap (state == 0) must be a lowest-level trap
   (~trap_ix <= numregions(tstruct)~).
4. Every nonempty parent trap (trap_ix > numregions and state > 0) must have all
   its immediate children (~subtrapsof~) also FULL in the network.

** Capacity definition

The canonical capacity for comparing V against is ~TrapGeometry.capacity~, which
equals ~trapvolumes[t] - subvolumes[t]~ for a parent trap (net of subtraps) and
~trapvolumes[t]~ for a lowest-level trap.  This is the physically meaningful
quantity: the volume the trap accumulates *above* whatever its subtraps already
hold.  All FULL/EMPTY/TRANSITORY comparisons use this value.  It must be
documented clearly wherever used.

** Inflow model

- Inflow is *constant in time*.  The caller supplies a constant rate per trap
  (and later per NBSSystem).
- Inflow is *additive*.  A trap's total inflow is the caller-specified inflow
  for that trap *plus* whatever the flow paths route into it from upstream
  (spill from upstream FULL traps, less throughput-capped infiltration in
  transit).  Flow paths are instantaneous and lossy.
- With constant inflow, a network reaching steady state without any trap
  overflowing is a definitive indication that no further event will ever occur.
  In that case the returned event time is ∞.

** State vector and ODE dimensionality

- The state is each trap's stored water volume (net of subtraps).  The state
  vector covers *all* nt traps in the ~DynNetwork~ (FULL, TRANSITORY, and EMPTY).
- FULL traps participate in the ODE: their rate is ~dV = inflow - footprint_infil -
  max(inflow - footprint_infil, 0)~, which is 0 while the trap is adequately
  supplied, and negative once its inflow drops below its losses.  Including FULL
  traps in the ODE is necessary to detect mid-integration FULL→TRANSITORY
  transitions (e.g. culvert inflow from a draining TRANSITORY trap diminishes
  until the FULL trap can no longer sustain its full status).
- The rate function must use ~min(V, C)~ when evaluating the water level for a
  FULL trap (~_surface_level~ already does this) to prevent ODE-stage overshoot
  above C from producing physically impossible states.
- The physical floor V >= 0 is enforced in the rate function: if V <= 0 and the
  computed dV < 0, clamp dV = 0.  This prevents ODE integration from pushing an
  EMPTY trap negative.

** Events

The solve integrates forward and stops at the *first* event:

| Event               | Condition                                 | Callback condition     |
|---------------------+-------------------------------------------+------------------------|
| ~:fill~ (type-1)    | TRANSITORY trap V reaches C               | ~C - V → 0~            |
| ~:empty~            | TRANSITORY parent-trap V reaches 0        | ~V → 0~ (parents only) |
| ~:unspill~ (type-2) | FULL trap's net inflow crosses 0 downward | ~inflow - loss → 0~    |
| ~:none~             | No evolving trap; rate ≈ 0 everywhere     | stagnation or pre-check|

Conditions checked *before* the ODE (fast paths):
1. Any FULL trap with ~inflow - footprint_infil < 0~ at t=0 → return ~:unspill~
   immediately (no need to integrate).
2. All evolving traps at steady state (rates ≈ 0) → return ~:none~ immediately.

Events detected *during* the ODE via ~VectorContinuousCallback~:
- ~:fill~: one condition per TRANSITORY trap: ~C_i - V_i~ crossing zero.
- ~:empty~: one condition per TRANSITORY *parent* trap (~trap_ix > numregions~):
  ~V_i~ crossing zero.  *Not registered for lowest-level traps* — EMPTY→TRANSITORY
  does not change topology.
- Stagnation: one condition per evolving trap with nonzero initial rate:
  ~dv0_i * dV_i~ crossing zero (rate sign change → steady state).
- ~:unspill~: one condition per FULL trap: ~inflow_i - footprint_infil_i~ crossing
  zero downward (net inflow goes negative, trap starts draining).

** Return values and in-place mutation

~solveDynNetwork!~ is a mutating function (bang convention).  It updates the
~state~ vector *in place* and returns a named tuple of scalars only:
- ~time~: time of the event, or ~Inf~ if steady state
- ~trap~: global trap index (into ~TrapStructure~) where the event occurred, 0 if none
- ~kind~: ~:fill~, ~:empty~, ~:unspill~, or ~:none~

The ~state~ argument is written with the final trap volumes at the event time.
Clamping is applied directly into ~state~: the triggering trap is set to exactly
C (for ~:fill~) or exactly 0 (for ~:empty~).

Rationale: the outer loop calls the solver once per event and owns the state
vector throughout.  Mutating in place avoids allocating a new nt-element Float64
array per call, which accumulates for large networks with many events.  The ODE
solver internally copies the initial condition, so the single up-front copy
~V0 = Float64.(state)~ is unavoidable; all other copies are eliminated.

The state for FULL traps that remained FULL (not the triggering trap) may have
tiny ODE-induced drift away from exact C.  The caller is responsible for
clamping these to exactly C before the next call (consistent with the caller's
authoritative ~full_traps~ record).

** TRANSITORY→EMPTY and parent traps

A parent trap's capacity is net of its subtraps (volume *above* both children's
spillpoints).  A nonempty parent has V > 0, which implies all its children are at
their own capacity (submerged).  When the parent's V reaches 0 (water level drops
to the merger elevation), the children are exposed.

The ~:empty~ event signals that the caller must remove the parent and all its
children from ~full_traps~, set their states to ~prevfloat(C)~, and rebuild the
network.  If a child was not genuinely draining, a ~:fill~ event fires on the
next call after an infinitesimal dt.

#+BEGIN_SRC julia
function _validate_network(tstruct::TrapStructure,
                           net::DynNetwork,
                           state::AbstractVector{<:Real},
                           geom::Vector{TrapGeometry})
    nreg = numregions(tstruct)
    nt   = length(net.traps)
    @assert length(state) == nt
    trap_map = Dict(net.traps[i].trap_ix => i for i in 1:nt)
    for i in 1:nt
        trap = net.traps[i]
        V    = state[i]
        C    = geom[i].capacity
        if V == C                               # FULL
            trap.spill_path > 0 ||
                error("FULL trap $(trap.trap_ix) has no spill path (spill_path == 0)")
            if trap.trap_ix > nreg              # parent trap: children must be FULL
                for child in subtrapsof(tstruct, trap.trap_ix)
                    ci = get(trap_map, child, 0)
                    ci > 0 ||
                        error("FULL parent trap $(trap.trap_ix) is missing child $child in network")
                    state[ci] == geom[ci].capacity ||
                        error("FULL parent trap $(trap.trap_ix) has non-FULL child $child")
                end
            end
        elseif V == 0.0                         # EMPTY
            trap.trap_ix <= nreg ||
                error("EMPTY parent trap $(trap.trap_ix) must not be in network when EMPTY; use its subtrap instead")
        else                                    # TRANSITORY
            trap.spill_path == 0 ||
                error("TRANSITORY trap $(trap.trap_ix) has spill_path > 0 (should only spill when FULL)")
        end
    end
end

function _event_conditions(p, evolving, nreg::Int, inflow0)
    conds = EventCondition[]
    for e in evolving
        push!(conds, EventCondition(:fill, e))
        p.net.traps[e].trap_ix > nreg &&
            push!(conds, EventCondition(:empty, e))
    end
    evolving_set = Set(evolving)
    for i in eachindex(p.net.traps)
        i in evolving_set && continue
        inflow0[i] - p.footprint_infil[i] > 0 &&
            push!(conds, EventCondition(:unspill, i))
    end

** DONE Steady-state via DiscreteCallback (~_build_steadystate_callback~)

A ~VectorContinuousCallback~ steady-state condition of the form ~max(|dV[e]|) - abstol~
fails for step-function infiltration: near the Zeno oscillation point the rate
alternates ±0.2 / -0.1 and never approaches zero.  Instead, we detect steady state
by observing that the *state* converges even when the rate does not.

~_build_steadystate_callback~ returns a ~DiscreteCallback~ that fires when
~|u[e] - uprev[e]| ≤ abstol + reltol·|uprev[e]|~ for all evolving traps, where
~uprev~ is the state at the previous accepted ODE step.  This detects both:

- *Smooth equilibria* (rate → 0): the state barely changes per step.
- *Zeno convergence* (step-function infiltration): the ODE oscillates at a sign-flip
  equilibrium with geometrically shrinking amplitude; accepted steps become tiny;
  |Δu| per step drops below the tolerance.

To avoid false positives the callback requires *n_consecutive* (default 3)
consecutive such tiny steps before firing:

- A single tiny step occurs transiently at each discrete cell-flooding transition
  (rate discontinuity) and during VectorContinuousCallback root-finding near a
  ~:fill~ event.  These are isolated events followed by normal-sized steps.
- Sustained tiny steps (≥ 3 in a row) only occur at genuine equilibria.

#+BEGIN_SRC julia
function _build_steadystate_callback(evolving, abstol, reltol = 1e-6; n_consecutive = 3)
    counter = Ref(0)
    function condition(u, t, integrator)
        tiny = all(abs(u[e] - integrator.uprev[e]) <=
                   abstol + reltol * abs(integrator.uprev[e]) for e in evolving)
        tiny ? (counter[] += 1) : (counter[] = 0)
        return counter[] >= n_consecutive
    end
    return DiscreteCallback(condition, terminate!; save_positions = (false, false))
end
#+END_SRC

The callback is combined with the topology ~VectorContinuousCallback~ via
~CallbackSet(cb_topo, cb_ss)~ in ~solveDynNetwork!~.  When it fires, ~event.kind~
stays ~:none~, so the driver returns ~(Inf, 0, :none)~ as usual.

Key properties:
- All topology events (~:fill~, ~:empty~, ~:unspill~) continue to terminate immediately
  via the VectorContinuousCallback.
- Correct regardless of rate history: a trap that briefly stagnated and then resumed
  (e.g., when a culvert inlet floods) continues integration without false termination.
- Works for any future inflow source (NBS, time-varying culverts) without modification.
- The pre-check ~all(|du0[i]| ≤ abstol for i in evolving)~ guards the initial condition:
  if all rates are already near zero at t=0, return ~:none~ without running the ODE.

* Invariants and caller protocol (summary)

A valid ~solveDynNetwork!~ call requires the following invariants, maintained by
the caller:

1. FULL trap: V == C exactly, spill_path > 0, all immediate children FULL.
2. TRANSITORY trap: 0 < V < C strictly, spill_path == 0.
3. EMPTY trap: V == 0 exactly, trap is a lowest-level trap (no subtraps).
4. Nonempty parent: all its children are FULL (enforced by network construction
   and the entry validator).

These invariants are checked by ~_validate_network~ and enforced by the caller
using the event-response protocol in the "Caller's responsibility" table above.

The caller also maintains the ~state~ vector after each event:
- ~:fill~:    ~state[T]~ is already clamped to C[T] on return; add T to ~full_traps~.
- ~:unspill~: set ~state[T] = prevfloat(C[T])~ before the next call.
- ~:empty~:   set ~state[A] = state[B] = prevfloat(C)~ for children A, B before
              the next call.
- ~:none~:    ~state~ unchanged; no further calls needed.
