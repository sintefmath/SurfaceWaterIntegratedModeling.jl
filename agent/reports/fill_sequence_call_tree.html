How the pieces fit

Three ways into the ODE solveDynNetwork!

predict estimates a context's next event on a copy of its state, commit advances the real state to a known time, finalize settles every context to period end. All three run under the context's cached extern_inflow, which is what makes them order-independent of any intervening spillgraph update. NBS just adds layer states to the state vector and a second, layer-aware steady-state callback.

★ NBS state continuity

nbs_state — a Dict{Int,Vector{Float64}} owned by the NetworkDriver, not by the TrapStructure — is the single source of truth for layer storage, keyed by each placement's stable id. Seeded into contexts via _nbs_layer_block, persisted back via _store_nbs_state! at every harvest and at finalize. That round-trip keeps storage continuous across both structural change and weather periods.

◆ The quiet-event skip gate

_touch_affected_networks! runs only when a network member fired (topology) or one of its inflow regions changed (dynamics). If neither holds, the pass is skipped — cached state and prediction stay exact and the event costs zero ODE solves. The dominant runtime win for a small network in a large terrain.

◆ Mutate, don't retrace

The driver builds its components once per weather period, then mutates the live Vector{DynNetwork} in place per event via apply_fill! / apply_unfill! / apply_empty! — grow, detach, subsume, fuse. Committed node volumes and NBS layers are harvested first, so they survive the structural change and reseed the rebuilt contexts. The old full-retrace path is retired.
